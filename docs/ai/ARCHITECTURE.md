# 授渔架构

## 运行形态

```text
index.html
  └─ js/app.js (ES module, 单入口)
       ├─ js/db.js              IndexedDB 封装
       ├─ js/programs-store.js  专业体系修订/隐藏状态
       ├─ js/studio-store.js    备课项目
       ├─ js/impact-store.js    教学应用成效
       ├─ js/engine.js          生成与结构模板
       ├─ js/quality-engine.js  10 维质检
       ├─ js/export.js          DOCX/XLSX/MD/打印
       ├─ js/files.js           本机文件解析
       ├─ js/ai.js / ai-*.js    可选增强模式
       └─ 静态数据模块          programs/knowledge/curriculum/templates
```

## 路由（`parseRoute`）

## 状态与存储

- 全局 `state`：路由、会话、材料、备课流程、质量选择、模态框、侧栏状态。
- `db`：`jiangbei_v2`，会话/消息/文件/自定义知识/反馈。
- `shouyu_programs_v1`：专业体系修订、隐藏记录。
- `shouyu_studio_v1`：`bundles` 备课项目、文档、质量历史、审核、导出。
- `shouyu_impact_v1`：应用成效记录。
- localStorage：课程/项目上下文、草稿、质检权重/忽略项、向导状态、兼容回退。
- `shouyu.teaching.v1`：教师真实录入的授课记录（localStorage；已纳入完整备份和恢复；清空本机数据时一并清除）。

## 页面渲染

`renderApp()` → `renderSidebar()` + `renderTopbar()` + `renderView()`。

每个页面由 `renderXxxPage()` 返回 HTML 字符串，事件由全局 `data-action` 委托处理；弹窗由 `openModal()`/`renderModal()` 统一管理。

## 已知工程问题

1. `js/app.js` 是单文件巨石，路由、视图、事件、弹窗、导出和 AI 逻辑混在一个文件。
2. CSS 五层叠加，历史规则和层叠覆盖多；改一处需确认四层优先级。
3. 部分类名/页面已废弃但保留（旧 chat、旧工作型布局）。
4. 没有构建期类型检查和 lint；测试依赖静态服务器与 Playwright。
5. 页面宽度、字号在上一轮已统一，但组件仍存在局部专用样式。

## 架构调整原则

- 不拆技术栈、不引入框架、不重写业务。
- 先抽设计 token 与页面壳，再逐页替换。
- 新增页面/模块只允许使用真实本地记录；没有数据时显示明确空状态。
- 优先合并语义重复的入口，不增加一级菜单数量。
- 所有结构调整必须保留旧路由可访问，避免书签失效。

## 已实施：课程授课记录

- 模块：`js/teaching-store.js`。
- 入口：课程工作空间 → 授课记录。
- 字段：课程、章节、任务、关联项目、日期、班级别名、人数、学时、资源版本、课堂事实、下一步反思。
- 不保存学生姓名、学号、联系方式；没有数据时显示空状态。
- 汇总：记录数、学时、最近日期；完整备份包含 `teaching.records`。
- 测试：`tests/teaching-store.test.mjs` + E2E 空状态入口检查。
