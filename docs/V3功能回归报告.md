## 二、实际页面走查

### 场景 A：第一次从课程开始完整备课

路径：

```text
我的课程 → 完整知识包课程 → 课程工作空间
→ 开始备课 → 第 2 步（章节/任务已带入）
→ 第 3 步 → 第 4 步 → 生成
```

实测：

- 点击 5 次；
- 页面路由跳转 2 次；
- 生成 10 类文档；
- 项目质检 84 分；
- 当前步骤进入“编辑与质检”；
- 0 页面错误；
- 未要求重新选择课程；
- 项目、课程、章节、任务关联正确。

### 场景 B：刷新后继续当前项目

实测：

- 生成项目后刷新浏览器；
- `shouyu.workspace.context.v1` 保存 `courseId / chapterId / taskId / projectId`；
- 刷新后 `/studio` 自动打开当前项目；
- 左栏 10 个文档、右栏 10 个质检维度；
- 不需要重新选择课程或项目。

### 场景 C：从知识库带入资料

实测：

- 知识库搜索“物料分拣”；
- 打开资料；
- 点“用于备课”；
- 自动匹配 PLC 技术及应用，进入第 2 步；
- 参考材料卡片 1 份；
- 生成后参考材料进入项目来源；
- 质检 84 分；
- 导出 DOCX 成功。

### 场景 D：旧数据兼容

代码路径：

- 启动时读取原有 `shouyu.studio.v1` 成果；
- 缺失 `qualityHistory` → 由当前 quality 生成首条记录；
- 缺失 `exports` → 初始化为空；
- 缺失 `context` → 初始化为空对象；
- 缺少全局上下文 → 从最近项目恢复；
- 写回不设置 `_contentChanged`，不改变版本号；
- 不删除旧字段、不更换 bundle id。

说明：旧版 bundle 的迁移逻辑已实现并在启动链中执行；本轮没有构造外部旧数据库文件做单独的破坏性测试，旧成果仍通过原有 E2E 备份恢复路径验证。

## 五、可访问性与响应式

- 1440 下项目工作区计算为三栏；
- 1024 以下辅助面板下移；
- 768 / 390 单列，文档目录横向/独立滚动，页面无横向溢出；
- 移动端项目正文中表格强制 100% 宽，避免撑破页面；
- 四个核心导航在 390px 下通过抽屉访问。

## 六、已知限制

1. 中栏是文档阅读/编辑入口，复杂结构化编辑仍打开现有编辑器，不是完全内联编辑。
2. 质量面板点击问题可定位文档，但“课程知识包”类问题没有对应原文，只能提示并打开完整审阅。
3. 质量检测历史目前写入 `qualityHistory`，还没有独立时间线 UI。
4. 课程列表默认只显示前 80 门，需要搜索或教学单位筛选。
5. 没有真人教师可用性实验；只有自动化走查。
6. 基础层仍有少量死 CSS 未物理删除。
7. 未做真机 iOS / Android 测试。

## 七、结论

V3 的课程上下文、备课项目、项目文档工作区、内嵌质量检测和成果归档已经形成一条连续路径。旧路由、专业库、知识库、AI、10 类资源、质检、编辑器、版本、导出、文件解析和备份恢复均保留。没有通过删除功能来制造“简化”的假象。
