# 授渔 V2.2 · 操作体验整改报告

> 日期：2026-11-17  
> 线上地址：<https://htfyu.github.io/shouyu-teacher/>  
> 主题：不以视觉美化为目标，降低第一次使用的操作成本。  
> **说明：本轮没有真实教师参与可用性实验。下列“任务测试”是由 Playwright 按真实页面路径执行的自动化走查，用于发现操作断点和验证数据，不冒充真人测试结果。**

## 一、整改前的主要问题

1. “新建备课”有两个行为：侧栏/顶部回到首页，首页进入 `/studio`。
2. 顶部“新建备课”实际新建的是 AI 对话。
3. 新建备课默认 PLC 演示课程，其他专业教师第一步就要改课程。
4. 备课页一次显示全部课程、章节、对象、学时、条件字段，像大型表单。
5. 生成前没有步骤状态，不能保存草稿，刷新或退出会丢失输入。
6. 侧栏 13 个一级入口，“质量检测 / 质量检测中心”等命名不一致。
7. 生成后左侧仍是完整配置表单，容易误改；右侧文档空间被辅助卡片挤压。
8. 教学资源只能阅读，不能带入备课。
9. 旧成果编辑后没有明显的版本结果，用户不知道是否保存新版本。

## 二、已落地的整改

### 1. CSS 加载链

`index.html` 当前顺序：

```text
assets/styles.css
assets/ui-refresh.css
assets/work-theme.css
```

浏览器实际计算样式已验证：

| 选择器 | 1440px 计算结果 |
|---|---|
| `.work-home-layout` | `display:grid`，`777.625px 286px` |
| `.studio-workspace` | `display:grid`，`300px 775.625px`（辅助栏默认收起） |
| `.quality-workspace` | `display:grid`，`286px 505.625px 300px` |
| `.kb-workspace` | `display:grid`，`190px 885.625px` |

根 Token `--brand-line` 实际计算为 `#cad6cd`，说明 `work-theme.css` 已进入线上加载链，而不是只存在于源码。

### 2. 入口统一

- 侧栏/顶部：**开始备课 → 六步第 1 步**；
- 首页：**新建备课 → 六步第 1 步**；
- 专业库课程：**开始备课 → 第 2 步，带入课程**；
- 常用课程：**→ 第 3 步，带入课程/章节/任务**；
- 教学资源：**用于备课 → 带入参考材料**；
- 顶部和更多菜单：**新建对话**，只创建教学对话；
- 快捷键 `N`：开始备课，不再回首页；
- 新建第 1 步不预选 PLC，不出现“暂无公开资料”的占位课程。

### 3. 导航精简

核心 5 项：

1. 教学工作台
2. 备课中心
3. 专业与课程
4. 教学资源
5. 教学成果

更多功能折叠 8 项：质量检测、知识图谱、资料中心、模板库、教学应用成效、历史记录、系统设置、使用说明，以及“新建对话”。质量检测仍保留独立入口。

### 4. 六步备课

1. 选专业课程；
2. 定章节任务；
3. 教学配置；
4. 确认并生成；
5. 编辑与质检；
6. 保存与导出。

每一步有步骤条、当前标题、一个主操作、上一步。教学对象和学时给默认值；教学条件可以留空；补充目标折叠；第 2—4 步自动保存草稿。

### 5. 双栏工作区

- 生成后默认双栏：左侧本次教学配置摘要，右侧文档；
- 知识包、知识点、来源、质检放在可收起辅助栏；
- 辅助栏默认收起，点击“资料”展开；宽屏可形成三栏；
- 不再让多个知识卡片挤压文档。

### 6. 草稿

- 草稿键：`shouyu.studio.wizard.v1`；
- 保存课程、章节、任务、对象、学时、条件、补充目标、参考材料、步骤；
- 工作台、备课中心显示“继续草稿”；
- 刷新/关闭页面后仍可恢复；
- 生成后草稿清除，成果自动进入成果库。

### 7. 参考材料进入备课

- 教学资源右栏增加“用于备课”；
- 资源作为 `referenceDocs` 写入教学资源包来源，不会假装改写了知识包；
- 第 1/2/3/4 步显示参考材料卡片，可移除；
- 参考材料不会自动改写教师内容，也不会替代课程知识包。

### 8. 质量与成果

- 第 5 步显示质检分数、问题数、待教师核对数；
- 可进入完整三栏审阅；
- 成果编辑自动保存，`_contentChanged` 触发新版本；
- 版本历史保留最近 4 个旧版本，可恢复。

## 三、自动化任务走查

> 浏览器：Microsoft Edge headless；桌面 1440×1000。  
> 计时是脚本执行时间，不代表真人耗时；页面跳转数按 `history.pushState` 统计。

| 场景 | 路径 | 用户动作 | 页面跳转 | 脚本耗时（非真人） | 结果 | 页面错误 |
|---|---|---|---:|---:|---|---:|
| A 新教师第一次生成 | 工作台 → 新建备课 → 选专业/课程 → 章节 → 配置 → 生成 | 5 次点击 + 2 次下拉选择 | 1 | 4.0 秒 | 10 类文档；质检 72；进入第 5 步 | 0 |
| B 老教师继续编辑 | 演示生成 → 教学成果 → 打开 → 编辑标题 → 自动保存 → 版本 | 5 次点击 | 2 | 6.1 秒 | v1 → v2；历史 2 条；标题修改保存 | 0 |
| C 查资料用于备课并导出 | 教学资源搜索 → 阅读 → 用于备课 → 选课程 → 生成 → 质量 → 导出 | 9 次点击 | 2 | 5.6 秒 | 参考材料进入第 2 步；质检 84；DOCX 下载成功 | 0 |

### 数据是否正确保留

- A：课程、章节、任务、10 类文档、质检分数均保存；刷新后成果出现在工作台/成果库。
- B：编辑后版本从 v1 变 v2，旧版本仍在历史；没有覆盖旧内容。
- C：参考材料在 `referenceDocs` 和成果来源中；质量页可打开；DOCX 文件名与课程/任务一致。
- 草稿：保存“32 人、6 学时”后回工作台，显示未完成草稿；恢复后值与步骤一致。

### 仍然会让人停顿的地方

1. 第 1 步专业下拉有 56 项，原生选择器可用但没有拼音搜索；第一次使用可能要找一会。
2. 刷新后草稿以横幅出现，需要再点一次“继续草稿”；没有自动打开，避免打断用户。
3. “行业通用参考”课程能生成，但质检分数通常低于有完整知识包的课程；新教师可能不理解原因。
4. 第 1 步的“专业”是 56 项平铺，未按系部分组展开为两级选择。
5. 质量检测没有历史快照，“重新检测”会覆盖当前报告。

## 四、可量化的简化

| 项目 | 整改后 |
|---|---|
| 一级导航 | 5 项 |
| 新建备课入口 | 全部进入同一六步流程 |
| 新建默认课程 | 无；必须选择 |
| 备课填写步骤 | 1 步只显示 1 组字段 |
| 草稿 | 自动保存 + 手动保存 + 刷新恢复 |
| 生成后辅助面板 | 默认收起 |
| 教学资源到备课 | 1 次“用于备课” |
| 成果版本 | 自动生成新版本，历史可恢复 |

未保留旧版可比的点击埋点，因此不宣称“节省了 X% 时间”。

## 六、没有做的事

- 没有请真实教师做可用性实验；
- 没有做眼动/录屏/问卷；
- 没有为“减少时间”编造百分比；
- 没有删除任何原有路由、专业库、AI、知识库、质检、编辑器、导出或备份功能。

## 七、建议下一轮

1. 第 1 步改为“系部 → 专业组 → 专业 → 课程”或加入搜索；
2. 草稿自动恢复为可关闭的提醒；
3. 质量检测历史快照；
4. 真机移动端测试；
5. 找 3—5 位真实教师做任务测试，记录完成时间与求助点。
