## 一、现状审计

### 1. 技术栈与部署

| 项 | 现状 |
|---|---|
| 部署 | GitHub Pages，纯静态，固定地址 `https://htfyu.github.io/jiangbei-teacher/` |
| 前端 | 原生 ES Modules + 手写 CSS，无框架、无构建步骤 |
| 后端 | 无。页面只请求本站静态资源 |
| AI | 无外部大模型。`js/engine.js` 为本地规则、知识检索与结构化模板引擎 |
| 存储 | `localStorage`，键 `jiangbei.workspace.v2`；历史上限 36 条 |
| 知识库 | 9 份校本示例材料 / 51 个可检索章节；只覆盖部分工科专业，安全仅电工 / PLC |
| 文件 | 仅本机读取 `.txt / .md / .csv / .json`，最多 3 份、单份 160KB，内容截断 8000 字 |
| 导出 | HTML `.doc`、浏览器打印 / 另存 PDF、Markdown、复制 |
| 测试 | 无自动化测试框架。此前仅用 Playwright 脚本做过浏览器手工回归，脚本未入仓库 |

### 2. 源码结构

| 文件 | 行数 / 体量 | 职责 |

| `js/engine.js` | ≈2,285 行 / 84KB | 知识检索、场景生成、边界规则、多轮改参、合规检查 |

### 3. 现有功能调用链

```text
首页场景卡 / 对话输入
  → app.js 表单校验 / 参数收集
  → engine.js generate()
      → knowledge.js 知识库与任务画像
      → 规则检索 + 结构化模板
      → compliance / sources
  → app.js 渲染结果卡 + 引用来源 + 合规自检
  → export.js 复制 / Word / 打印 / Markdown
  → localStorage 保存历史
```

### 4. 已确认的限制与缺陷（以当前源码为准）

1. **不是大模型**：无 AI 调用；生成由模板与规则完成。
2. **无后端**：无法安全托管 API Key；GitHub Pages 不能提供运行时服务端。
3. **专业知识覆盖不足**：缺少 12 个专业各自的独立知识包；安全知识只覆盖电工 / PLC。
4. **检索是关键词 / 字符 n-gram**：没有真正的语义向量检索，也没有混合排序评估。
5. **文件能力弱**：不支持 DOCX / PDF / XLSX / PPTX；长文档截断；无 OCR；无资料库。
6. **历史只在 localStorage**：容量有限、跨设备不同步；不支持分类、重命名、批量删除、备份恢复。
7. **结果不可编辑**：只能查看 / 复制 / 导出；没有实时预览、拖动排序、撤销恢复。
8. **隐私检测基于格式正则**：不能识别“学生张三”等弱格式；没有人工确认、自动脱敏与发送前审查。
9. **无测试体系**：无单元测试、无固定回归脚本、无 API 测试。
10. **教学成果导出格式有限**：没有真正的 DOCX（当前是 HTML .doc）、XLSX、规范 PDF 导出。

### 5. 现有优势（必须保留）

- 明确的角色边界、超范围拒绝规则；
- 知识库引用可回溯到章节；
- 参数澄清、多轮条件记忆；
- 五场景成果闭环，移动端与桌面均可用；
- 默认本地优先、数据不上传；
- 黑白线稿品牌识别度高；
- 无框架依赖，部署轻量。

## 二、目标架构

```text
┌────────────────────────────────────────────────────────────┐
│ GitHub Pages（静态前端）                                    │
│                                                            │
│  UI 层：工作台 / 对话 / 知识库 / 资料中心 / 历史 / 设置       │
│  编辑器：分栏预览、块编辑、拖动排序、撤销恢复、自动保存         │
│                                                            │
│  AI Adapter（js/ai.js）                                     │
│   ├─ 本地模式：现有规则引擎（始终可用，作为回退）              │
│   ├─ AI 体验通道：公开无密钥推理，需显式同意（仅演示）         │
│   └─ 安全代理：调用 Cloudflare Worker / Vercel Function       │
│         └─ 密钥只存在服务端环境变量，浏览器永远看不到           │
│                                                            │
│  隐私网关（js/privacy.js）                                   │
│   └─ 发送 / 上传前扫描 → 人工确认 → 自动脱敏                   │
│                                                            │
│  资料解析（js/files.js，按需加载）                             │
│   ├─ TXT/MD/CSV/JSON 原生                                  │
│   ├─ DOCX：mammoth                                         │
│   ├─ PDF：pdf.js + 可选 Tesseract OCR                      │
│   ├─ XLSX：SheetJS                                         │
│   └─ PPTX：JSZip + OOXML 解析                              │
│                                                            │
│  数据层（js/db.js，IndexedDB）                               │
│   ├─ conversations / knowledge / files / settings / meta    │
│   ├─ localStorage 迁移 + IDB 自动回退                        │
│   └─ JSON 备份 / 恢复 / 数据清理                             │
└────────────────────────────────────────────────────────────┘
              │ 仅 AI 增强模式且用户确认后
              ▼
┌────────────────────────────────────────────────────────────┐
│ 可选安全后端（server/）                                     │
│ Cloudflare Worker 或 Vercel Function                       │
│ 环境变量：AI_API_KEY / AI_BASE_URL / AI_MODEL / ALLOWED_ORIGINS │
│ 特性：CORS 白名单、请求大小限制、超时、流式 SSE、密钥不出服务端 │
└────────────────────────────────────────────────────────────┘
```

### AI 双引擎

- **本地模式**：现有规则、知识检索、结构化模板；无网络依赖，保证可用与安全。
- **AI 增强模式**：调用大模型，结合检索片段、当前课程参数与历史上下文生成 / 改写成果。
- 每次 AI 调用前经过隐私网关；AI 失败时保留本地草稿，可一键重试或回退。
- AI 输出强制标注“AI 辅助草稿 / 待人工审核”；安全类场景继续以知识库为硬约束。

### AI 实时体验通道的边界

GitHub Pages 本身不能托管密钥。为了在**不暴露任何密钥**的前提下让线上作品具备真实大模型能力，体验通道使用无密钥的公开推理服务（`text.pollinations.ai`，匿名模型 `openai-fast`）：

- 不包含任何 API Key；
- 首次使用必须显式同意第三方数据传输，并先经过本地隐私检查；
- 仅作演示；生产环境应切换到 `server/` 中的安全代理；
- 服务不可用时自动回退本地引擎，并提示原因。

这不是“用模板冒充 AI”：体验通道是真实流式 LLM。但它不是生产级私有部署；生产部署路径见 `server/README.md`。

## 三、分阶段计划与验收

### P0：核心能力

1. 安全 AI 适配层：本地 / AI 双模式，流式输出、取消、重试、回退；
2. AI 对话：知识库上下文、当前课程上下文、边界提示；
3. AI 教案增强：先生成本地结构化草稿，再由 AI 基于 KB 与参数改写并生成可编辑成果；
4. 隐私网关：AI 请求前扫描与用户确认；
5. 知识库扩展：12 个专业独立知识包 + 自定义资料 CRUD；
6. 安全代理源码与部署说明（Cloudflare Worker / Vercel）。

验收：AI 模式可流式输出；断网 / 401 / 429 时回退；无密钥出现在前端；12 专业检索可用。

### P1：教学效率

1. `js/files.js` 多格式解析、进度、预览、长文档分块；
2. 资料中心：文件列表、解析状态、加入知识库、删除、导出原文；
3. IndexedDB 存储、迁移、备份恢复、批量删除、标题修改、分类；
4. 成果编辑器：分栏预览、块编辑、拖动排序、撤销恢复、自动保存；
5. 导出 DOCX / PDF / XLSX / TXT / Markdown。

验收：DOCX/PDF/XLSX/PPTX 解析通过；IDB 重启后数据完整；备份导入可恢复；编辑与导出可用。

### P2：产品完善

1. 智能命题、教学反思、PPT 大纲、资源制作等扩展模块；
2. UI 统一、移动端 320/390/768 回归；
3. 性能：按需加载解析库、避免重复渲染、检索缓存。

### P3：长期

账号、云端同步、多用户权限、学校级知识库、教学数据分析。当前无后端与账号体系，P3 不伪装实现，仅在架构中预留。

## 四、真实性与安全约束

- 不虚构国家标准、行业标准、企业标准、设备参数与教学依据；
- 知识库材料明确标注“校本示例 / 待校审”；专业包采用可替换结构，不冒充官方教材；
- AI 输出必须人工审核；安全查询继续以知识库为硬约束；
- API Key 只存在服务端环境变量；
- 不把本地 IndexedDB 宣称为跨设备同步；
- 不能实际部署安全代理时，明确标注线上体验通道与生产部署差异。
