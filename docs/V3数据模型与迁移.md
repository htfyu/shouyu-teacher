## 二、备课项目模型

项目沿用原有教学成果包（schema `shouyu.studio.v1`），不另建第二套“项目库”。

```json
{
  "id": "studio_xxx",
  "schema": "shouyu.studio.v1",
  "version": 3,
  "status": "draft",
  "reviewStatus": "待审核",
  "courseId": "course-0010",
  "majorId": "major-008",
  "chapterId": "CH-PLC-01",
  "taskId": "TASK-PLC-01",
  "title": "课程 · 任务 · 教学资源包",
  "context": {
    "course": "PLC技术及应用",
    "major": "机电一体化技术",
    "chapter": "PLC 硬件、I/O 与安全边界",
    "task": "物料分拣站 I/O 分配与接线检查",
    "learners": "36 人",
    "hours": 4,
    "conditions": "…",
    "reviewStatus": "待教研组审核",
    "referenceDocs": []
  },
  "artifact": {
    "docs": ["10 类文档"],
    "sources": ["课程知识包/教师参考来源"]
  },
  "quality": { "overall": 84, "layers": {}, "problems": [] },
  "qualityHistory": [
    { "at": "ISO", "overall": 84, "problems": 1, "statusLabel": "…" }
  ],
  "history": [
    { "version": 1, "artifact": {}, "quality": {}, "reviewStatus": "待审核" }
  ],
  "exports": [
    { "type": "docx", "at": "ISO", "title": "…" }
  ],
  "createdAt": "ISO",
  "updatedAt": "ISO"
}
```

### V3 新增字段

| 字段 | 作用 | 兼容策略 |
|---|---|---|
| `qualityHistory` | 质检记录 | 旧项目首次加载时由当前 quality 生成 1 条 |
| `exports` | 导出文件记录 | 旧项目初始化为空数组 |
| `context.referenceDocs` | 教师从知识库带入的参考材料 | 旧项目缺省为空 |
| `history` | 原有内容版本 | 原逻辑保留 |

### 一个项目对应什么

```text
1 个课程 + 1 个章节 + 1 个典型任务
= 1 个备课项目
= 1 个资源包
= 10 类文档
= 1 组质量记录/版本/导出
```

同一门课的不同任务可以是不同项目；同一次备课不会拆成多个独立记录。

## 三、全局上下文

新增 localStorage：

```text
shouyu.workspace.context.v1
{
  "courseId": "course-0010",
  "chapterId": "CH-PLC-01",
  "taskId": "TASK-PLC-01",
  "projectId": "studio_xxx",
  "updatedAt": "ISO"
}
```

用途：

- 跨页面保留当前课程；
- 直接进入 `/studio` 恢复当前项目；
- 质量页自动打开当前项目报告；
- 成果页标记当前项目；
- 课程空间显示当前项目。

没有 context 时，首次加载从最近项目恢复；没有项目则显示课程/项目入口，不预选 PLC。

草稿单独保存：

```text
shouyu.studio.wizard.v1
{
  "courseId": "…",
  "majorId": "…",
  "chapterId": "…",
  "taskId": "…",
  "learners": "…",
  "hours": "4",
  "conditions": "…",
  "objectiveExtra": "…",
  "referenceDocs": [],
  "step": 3,
  "savedAt": "ISO"
}
```

## 四、兼容迁移

`bootstrapApp()` 在读取成果库后执行：

1. 读取旧 bundle；
2. `qualityHistory` 缺失 → 用当前 `quality` 生成 1 条；
3. `exports` 缺失 → 初始化为空；
4. `context` 缺失 → 初始化为空对象；
5. 若 workspace context 缺失 → 取最近项目的课程/章节/任务/项目；
6. 写回；写回不设置 `_contentChanged`，不增加版本号；
7. 再恢复当前上下文。

迁移是**加法**，不删除旧字段、不改变 bundle id、不重建存储。

## 五、路由兼容

| 旧路由 | V3 处理 |
|---|---|
| `/` | 保留，工作台 |
| `/programs` | 保留，作为“专业数据库”低频入口 |
| `/kb` | 保留，作为“专业知识库” |
| `/graph` | 保留，知识图谱 |
| `/studio` | 保留，改为项目中心 / 六步 / 项目工作区 |
| `/quality` | 保留，质量检测历史 |
| `/portfolio` | 保留，我的成果 |
| `/files` `/templates` `/history` `/settings` `/guide` `/impact` `/demo` | 保留 |
| `/chat/:id` | 保留 |
| 新增 `/courses` | 我的课程列表 |
| 新增 `/course/:id` | 课程工作空间 |

旧收藏链接仍可打开；旧 `/studio` 不再默认显示 PLC 配置，而是项目入口或当前项目。

## 六、导出记录

`studioExport` 成功后写入：

```json
{ "type": "docx", "at": "ISO", "title": "项目标题" }
```

- 最多保留 10 条；
- 导出失败不写入；
- 项目属性面板显示次数和最近格式；
- 成果卡显示导出次数。

## 七、边界

- 不把专业数据库原始表复制成新的项目表；
- 不把知识库文档复制进每个项目，只保存引用；
- 质量分数不是学校审核结论；
- 版本历史只保留最近 4 个内容版本；
- 数据仍然只在本机浏览器，跨设备需要完整备份；
- 生产 AI 安全代理与本数据模型无关，未改变隐私边界。
