# 专业知识库改造报告（2026-11-17 竞赛冲刺）

## 一、先区分五个概念

| 概念 | 数量 | 含义 |
|---|---:|---|
| 专业课程目录记录 | 567 | 原表课程总表的记录条数，包含占位/说明行；不等于 567 门完整课程 |
| 官方课程简介 | 13 | 原表明确标注有官方简介的课程 |
| 行业参考内容 | 其余课程 | 明确标注“行业通用参考/待完善”，不是学校官方课程资料 |
| 已建立知识包的课程 | 3 | 有章节、知识点、任务、目标、实训、设备、安全、考核和来源 |
| 已审核知识包 | 0 | 尚未有学院教研组正式审核记录；全部标“待教研组审核” |

首页、专业库、智能备课中心、质量检测中心统一使用这个口径，不再把 567 条目录记录说成 567 门完整课程。

## 二、三门标杆课程

| 知识包 | 课程 | 专业 | 规模 | 来源 |
|---|---|---|---:|---|
| `CUR-PLC-001` | PLC技术及应用 | 机电一体化技术 | 4 章 / 15 知识点 / 5 任务 | `PK-PLC-01/02` + S2/S3 |
| `CUR-ROBOT-001` | 工业机器人操作与应用 | 工业机器人应用与维护 | 4 章 / 16 知识点 / 5 任务 | `PK-ROBOT-01/02` + S6/S7/S8 |
| `CUR-NEV-001` | 新能源汽车底盘与维修 | 新能源汽车检测与维修 | 4 章 / 16 知识点 / 5 任务 | `PK-CAR-01/02` + S20/S21/S22 |

三门的专业方向分别为机电、工业机器人、新能源汽车，覆盖两个产业系，避免“同一专业复制三份”。

## 三、每个知识包包含什么

- 章节：章节号、标题、摘要；
- 知识点：标题、陈述、来源引用、来源类型、审核状态；
- 典型工作任务：情境、交付物、知识点关联、实施步骤、设备、安全、来源；
- 教学目标：知识 / 技能 / 职业素养；
- 重点、难点、能力；
- 实训设备与边界说明；
- 安全要求；
- 考核维度、权重、证据；
- 课程身份来源与内容来源分别标注；
- 审核人、审核状态、版本、更新时间、免责声明。

## 四、审核状态与来源

- 三门包均为 `pending`，`reviewer` 为空，`reviewedAt` 为空；
- 页面显示“审核人：未指定”“状态：待教研组审核”；
- 每门包的 `officialBasis` 只包含课程身份/专业介绍来源，不把内容来源冒充官方课程标准；
- 每门包的内容来源为 `PK` 校本示例，逐条 `§` 引用；
- 原表课程行来源编号错配，通过 `SOURCE_CORRECTIONS` 保留原值并给出建议修订；
- 未审核状态会影响质量分封顶（最高 84），不会显示“专家已认证”。

## 五、知识包不是怎么造出来的

- 没有用 AI 批量生成章节/知识点；
- 没有复制同一套模板到三门课：三门课的任务、设备、安全、评价和章节结构不同；
- 没有编造设备型号、扭矩、I/O 地址、软件版本；
- 没有把“知识点数量”当成“课程完整度”；
- 没有把行业参考标成学校官方资料。

## 六、仍待学校完成的工作

1. 由三个专业教研组逐条审核知识点、设备、安全、评价；
2. 审核后在系统中登记审核人、时间、意见和版本；
3. 修正原表来源编号错配并重新生成数据；
4. 再扩展到其他课程，每门课必须单独建设与审核，不能模板批量复制；
5. 课程知识包编辑 UI 和在线签字流程仍未实现。

**结论：** 当前达到“3 门可追溯、可演示、可质检的校本示例知识包”，不是“567 门完整课程知识库”，也不是“学院已审核课程标准”。
