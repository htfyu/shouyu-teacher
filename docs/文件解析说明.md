# 匠备 V2 · 多格式文件解析模块

本说明对应新增文件 `js/files.js`、`assets/vendor/`、`tests/files.test.mjs` 和 `tests/fixtures/`。

模块在**浏览器本地**完成文件解析，没有后端、没有上传接口；除明确启用 OCR 外，运行时不依赖 CDN。

> V2 已在 `js/app.js` 中接入：资料中心、按需解析、进度条、隐私确认、OCR 同意、加入知识库、预览与删除。本文档保留模块 API 说明。

---

## 1. 快速使用

```js
import { parseFile, chunkDocument, FileParseError } from "./js/files.js";

try {
  const parsed = await parseFile(file, {
    maxFileMB: 25,
    enableOCR: false, // true 表示用户已明确同意联网 OCR
    onProgress(event) {
      // event: { phase, progress, message, ...detail }
      console.log(event.phase, event.progress, event.message);
    }
  });

  // 长文不直接塞进一个 DOM 节点；按块渲染或送入工作流。
  const chunks = chunkDocument(parsed.text, { maxChars: 1000, overlap: 120 });
  console.log(chunks.length, chunks.stats.complete);

  if (parsed.needsOCR) {
    // 由界面弹出“将从 CDN 下载 OCR 依赖”的同意提示；
    // 用户同意后重新调用 parseFile(file, { enableOCR: true })。
  }
} catch (error) {
  if (error instanceof FileParseError) {
    console.error(error.code, error.message, error.details);
  }
}
```

可直接用 `new File([...], name, {type})` 或 `<input type="file">` / 拖拽得到的 `File`。
模块不会读取本地路径，也不会把文件内容发到服务器。

## 2. 对外 API

### 2.1 `parseFile(file, options)`

```ts
parseFile(file: File, options?: {
  onProgress?: (event: ProgressEvent) => void;
  maxFileMB?: number;       // 默认 25，可传 Infinity
  enableOCR?: boolean;     // 默认 false；true 即明确同意联网 OCR
  ocrLang?: string;        // 默认 "chi_sim+eng"
  ocrMaxPages?: number;    // 默认 3，上限 20；只处理前 N 个低文本页
  ocrCdn?: string;         // 仅替换主脚本 URL；默认见 OCR_CDN.scriptUrl
  ocrTimeoutMs?: number;   // 默认 60000
}): Promise<ParseResult>
```

`ParseResult`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `name` | string | 原文件名 |
| `size` | number | 字节数 |
| `type` | string | MIME；为空时按扩展名补全 |
| `title` | string | 核心属性 / 首个标题 / 首行 / 文件名回退 |
| `text` | string | 完整可读文本；PDF 会带 `## 第 N 页`，PPTX 带 `## 幻灯片 N`，XLSX 带工作表与行标签 |
| `blocks` | array | 段落、标题、表格、页、工作表、幻灯片等块，供引用定位 |
| `pages` | array | PDF：`{number,text,charCount,needsOCR,ocr}`；其他格式为 `[]` |
| `sheets` | array | XLSX：`{name,index,headers,rowCount,columnCount,text}`；其他为 `[]` |
| `slides` | array | PPTX：`{number,title,text,charCount}`；其他为 `[]` |
| `metadata` | object | 核心属性、页/表/片数、解析器版本、依赖库版本等 |
| `warnings` | string[] | 可展示给用户的降级提示；不是异常 |
| `needsOCR` | boolean | 当前结果是否仍有低文本 PDF 页需要 OCR |
| `charCount` | number | `text.length`，额外便利字段 |
| `blockCount` | number | 块数量，额外便利字段 |

**`blocks` 常用类型**：`heading`、`paragraph`、`list-item`、`blockquote`、`table`、`page`、`sheet`、`slide`、`json`、`code`。
块只保存纯文本与结构化元数据，不保存 HTML 字符串，不插入 DOM。

**进度事件**：

```js
{
  phase: "validate" | "read" | "dependency" | "parse" | "ocr" | "finalize" | "done",
  progress: 0..1,
  message: "给用户看的中文说明",
  // 可能附带 format/page/pageCount/charCount/...
}
```

- 进度对单次解析单调不降；
- `done` 为 1；
- 回调抛异常会被捕获，不影响解析；
- 库加载阶段有 `dependency`，PDF OCR 有独立的 `ocr` 阶段。

**错误**统一为 `FileParseError`：

```js
{
  name: "FileParseError",
  code: "...",
  message: "中文原因",
  details: { fileName, format, page, library, url, cause, partial }
}
```

| code | 含义 |
|---|---|
| `INVALID_FILE` | 不是可读 File/Blob 或缺少文件名 |
| `INVALID_OPTION` | `maxFileMB` 等参数非法 |
| `UNSUPPORTED_TYPE` | 扩展名/MIME 不在支持列表 |
| `FILE_TOO_LARGE` | 超过 `maxFileMB` |
| `READ_ERROR` | 浏览器读取文件失败 |
| `DEPENDENCY_UNAVAILABLE` | 本地 vendor 加载失败（网络、路径、MIME） |
| `PARSE_ERROR` | 文件损坏、格式不合法、解析库报错 |
| `ENCRYPTED_PDF` | PDF 有打开密码 |
| `OCR_UNAVAILABLE` | 已同意 OCR，但 CDN/worker/语言数据/Tesseract 不可用 |
| `OCR_FAILED` | OCR 已启动，但页面渲染或识别过程失败 |

OCR 失败不会把猜测文本写进结果；错误会拒绝整个 `parseFile`，`details` 里只提供页数/已提取字符数等诊断信息。

### 2.2 `chunkDocument(text, options)`

```js
const chunks = chunkDocument(text, {
  maxChars: 1000, // 默认 1000，必须是正整数
  overlap: 120    // 默认 120，必须 >=0 且 < maxChars
});

// chunks 是数组：
// {
//   id: "chunk-0001",
//   text: "……",
//   order: 0,
//   charStart: 0,
//   charEnd: 986
// }
//
// 数组本身还带统计：
chunks.stats;
```

`chunks.stats`：

```js
{
  totalChars, totalCodePoints, chunkCount,
  maxChars, overlap, overlapChars,
  coveredChars, coverageRatio, complete,
  firstChunkChars, longestChunk, shortestChunk, averageChunk,
  range: { from: 0, to: totalChars }
}
```

切分规则：

1. 优先段落空行 → 标题/换行 → 句末（`。！？!?；;` / `. `）→ 分句（`，,、：:`）→ 空白；
2. 如果单个不可断长串（例如 2500 个无标点字符）超过 `maxChars`，按字符安全硬切；**不丢字**，只是这一块没有自然边界；
3. `overlap` 是相邻块尾部与下块头部的重叠；会尽量对齐到句子/空白边界；
4. `chunks[i].text === 原文本.slice(chunks[i].charStart, chunks[i].charEnd)`；
5. `order` 从 **0** 开始；`id` 从 `chunk-0001` 开始，可用 `idPrefix` 改前缀；
6. 空文本返回空数组，`stats.complete === true`、`coverageRatio === 1`；
7. `charStart/charEnd` 是 JavaScript UTF-16 code unit 偏移；`totalCodePoints` 是 Unicode 码点计数；
8. `maxChars` 以 code unit 计。极端情况下（`maxChars:1` 且 emoji 在边界）会保留完整的代理对，单块可能比 1 多 1 个 code unit，但不会产生乱码。

> 分块只负责在内存中建立索引；应用应只渲染当前块/页，不要一次性把 `text` 或所有 `chunks` 插到 DOM。

### 2.3 可选清理

`disposeParser()` 会清空模块级依赖 Promise 缓存，便于长生命周期页面在脚本被宿主移除后重新加载。它不会终止正在进行的解析，也不会释放已经完成的解析结果。

## 3. 各格式行为

| 格式 | 解析方式 | 标题 | 要点 |
|---|---|---|---|
| TXT | 原生 `TextDecoder` + 段落 | 首个非空行 | 支持 UTF-8 BOM、UTF-16 BOM；非严格 UTF-8 尝试 GB18030 |
| MD | 原生逐行解析 | 一级标题 → 首个标题 → 行 | `heading` 块保留 level；原 Markdown 文本保留在 `text` |
| CSV | 原生 RFC4180 风格解析 | 文件名 | 自动识别逗号/分号/Tab；保留表头、行号、带引号逗号与单元格内换行 |
| JSON | 原生 `JSON.parse` + 递归 pretty print | `title/name/course` → 文件名 | 顶层键、数组、嵌套对象全部保留；语法错误给 `PARSE_ERROR` |
| DOCX | 本地 mammoth browser build | core properties `dc:title` → 首标题/段落 | 段落、标题、表格文本；图片不提取；mammoth 警告进入 `warnings` |
| PDF | 本地 pdf.js build + worker + CMaps | PDF `Title` → 首页首行 | 逐页 `getTextContent()`；低文本页标 `needsOCR` |
| XLSX | 本地 SheetJS | `Props.Title` → 首个表名 | 遍历所有工作表，第一行当表头，之后为行文本；不提取图表/图片 |
| PPTX | 本地 JSZip + DrawingML XML | core properties `dc:title` → 首片首行 | 遍历 `ppt/slides/slide*.xml`，按数字排序；提取 `a:t` 段落文本 |

### 3.1 PDF 与 OCR

- 每页去空白后少于 **20 个字符**，标记该页 `needsOCR: true`；只要存在低文本页，整个 `needsOCR: true`。
- `enableOCR: false`（默认）：返回已提取文本 + `needsOCR: true` + 明确警告；**不会**猜测或补写。
- `enableOCR: true`：只对按页序的前 `ocrMaxPages`（默认 3）个低文本页执行 OCR。
- 默认语言 `chi_sim+eng`；可传 `ocrLang: "eng"` 等减少下载。
- OCR 通过 canvas 渲染页面 → Tesseract.js 识别；页面文本替换为识别结果，并在 `metadata.ocr` 记录处理页、剩余低文本页、版本。
- **显式同意**在 API 层就体现为 `enableOCR: true`。调用方应先弹窗说明会访问：
  - `cdn.jsdelivr.net` 上的 Tesseract.js 脚本、worker/core；
  - `cdn.jsdelivr.net` 上的 `@tesseract.js-data/...` 语言数据。
- `ocrCdn` 只替换 Tesseract.js **主脚本**地址；其内部 worker/core/语言数据仍使用 Tesseract.js 默认 CDN。若要完全离线内网部署，需要自行托管完整 OCR 资源并修改这些默认路径。
- OCR 失败会抛出 `OCR_UNAVAILABLE` / `OCR_FAILED`，不写入任何占位文本。

## 4. 大文件、DOM 与隐私

- 默认 `maxFileMB = 25`，可配置；超过即 `FILE_TOO_LARGE`，不读取字节。
- 文件只进入内存（`ArrayBuffer`/File），不经过网络上传。
- 解析结果不会写入 DOM：`blocks`/`pages`/`sheets`/`slides` 是纯数据，`text` 是字符串；需要展示时请只渲染当前块/页。
- 普通解析的网络请求只有本站的 `assets/vendor/` 脚本、PDF worker 和本地 CMaps。
- OCR 是唯一会访问第三方 CDN 的步骤，且必须由调用方明确传 `enableOCR: true`。
- 本地至少需要浏览器支持：ES Modules、`TextDecoder`、`Blob`、`File.arrayBuffer`、`DOMParser`、`Canvas`（仅 OCR 渲染）。推荐现代 Chrome/Edge/Firefox。

## 7. 已知限制

1. **OCR**：只支持 PDF；只处理前 N 个低文本页；语言包和 worker 来自 CDN；中文识别质量依赖扫描清晰度，未做自动化稳定性验证。
2. **PDF**：加密 PDF 不自动解密；扫描件未同意 OCR 时只返回 `needsOCR`；没有标准字体包，极少数无嵌入字体页面可能字体警告；页眉页脚、表格结构不还原。
3. **DOCX**：mammoth 只提取正文主要结构，图片、页眉/页脚、脚注、文本框等可能缺失；表头由 `<th>` 或首行文本判断，格式复杂时可能不准确。
4. **XLSX**：第一行假定为表头；公式使用缓存/格式化值，不还原公式；合并单元格、图表、图片、批注、样式不提取。
5. **PPTX**：按 `slideN.xml` 数字顺序读取，未读取 `presentation.xml` 的演讲者排序；备注页、动画、图片内文字不提取。
6. **CSV**：仅自动识别逗号、分号、Tab；首行当表头；复杂转义/编码异常会在 `warnings` 提示。
7. **TXT/MD**：MD 只解析标题/列表/代码块等常见结构，不渲染；YAML front matter 不单独解析。
8. **文件大小**：默认 25 MB，整文件读入内存；没有流式 zip 解压防护，极端 zip bomb 不在保护范围。
9. **无后端**：所有解析在浏览器完成，不能处理需要服务器端 OCR/杀毒/格式转换的文件。
10. **应用接入**：已在 `js/app.js` 的资料中心与聊天附件中接入进度、隐私确认、OCR 同意、加入知识库与错误展示。

## 8. 应用侧接入清单

1. 在用户选择文件后调用 `parseFile()`；显示 `onProgress` 的 `message`。
2. 捕获 `FileParseError`，按 `code` 给不同提示；`FILE_TOO_LARGE` 不应重试同一文件。
3. 若 `ret.needsOCR` 且 `enableOCR` 未开启，展示“扫描件，需要 OCR 才能识别”的说明，不要直接生成教案。
4. 只有用户明确点击“同意联网 OCR”后才传 `enableOCR: true`，并告知 CDN 访问。
5. 使用 `chunkDocument(ret.text, { maxChars, overlap })` 建立块索引；只渲染当前块/页，不把完整 `text` 放入一个 DOM 节点。
6. 显示 `warnings`，尤其是编码回退、扫描页、空工作表、PPT 空页等。
7. 不把 `metadata` 中的原始作者/路径当作真实学生数据；测试夹具均为虚构。
