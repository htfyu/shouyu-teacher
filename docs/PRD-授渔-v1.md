# 授渔 PRD v1

> 状态：待审阅  
> 日期：2026-11-18  
> 依据：《授渔产品需求理解报告》最终版 v5（已确认）  
> 本文只定义产品需求，不定义视觉稿与代码实现。

---

## 1. 背景

职业院校教师同时承担教学、学生工作、竞赛与行政事务，能够用于认真备课的时间被严重压缩。结果是：

- 新教师不知道一堂工学一体化课程如何组织；
- 有经验的教师没有时间把每一堂课准备完整；
- 教学资料零散，教学设计与工作页、任务书之间容易不一致；
- 通用 AI 能生成文字，但缺少专业依据、来源说明和跨材料校验；
- 教师需要在多个工具或模块之间切换，重复录入相同信息。

授渔要解决的是：**帮助教师把一个具体课程中的典型工作任务，准备成一堂真正可上的课。**

---

## 2. 产品目标

### 2.1 核心目标

教师在授渔中完成一件事：

> 我要准备《综合布线》里的“网线制作”。

然后获得一套内容相互关联、有来源依据、经过教师修改与检查、可以直接导出的教学材料。

### 2.2 比赛目标

评委不需要作者现场讲解，自己打开网站操作，就能理解：

> 授渔是帮老师把一堂课完整准备出来的。

而不是：

> 这是一个会生成教案的 AI。

### 2.3 成功标准

- 新教师能沿着默认路径独立走通；
- 有经验的教师可以跳过、直接修改、快速完成；
- 五类核心材料内容一致、来源可辨；
- 思维导图、PPT 可逐步展开查看；
- 教材可以实际导入并识别；
- 合并版和分册版都能导出 Word 和 PDF；
- 全流程不跳模块、不重复录入、不出现花哨干扰。

## 3. 用户与原则

### 3.1 用户

| 用户 | 需要 |
|---|---|
| 新教师 | 方法、结构、示范、专业知识转化为教学内容的支撑 |
| 有经验教师 | 效率、初稿、快速检查、快速修改、复用 |

### 3.2 双用户原则

> 新教师获得方法和支撑，老教师获得效率和减负。

采用向下兼容：

- 默认路径为完整、可理解的新手路径；
- 熟手可以跳过确认、直接改、直接导出；
- 不拆“新手版/专家版”两套界面。

### 3.3 总交互原则

> 不要让教师操作系统，要让教师完成工作。

教师面对的是“网线制作这堂课”，不是“教案模块、工作页模块、质量检测模块”。

## 4. 范围

### 4.1 比赛演示范围

| 项目 | 内容 |
|---|---|
| 专业 | 计算机网络应用 |
| 课程 | 综合布线 |
| 典型工作任务 | 网线制作 |

只把“网线制作”做深做透，不铺开整个专业全部课程；但底层流程必须可迁移到其他课程。

### 4.2 第一阶段：核心主链路

- 选择课程与典型工作任务；
- 自动带入课程、任务、知识与资料上下文；
- 教学设计梳理与教师确认；
- 生成五类教学材料：
  - 教学设计；
  - 教案；
  - 信息页；
  - 工作页；
  - 实训任务书；
- 教师逐段检查、修改、删除；
- 整体审阅；
- 跨文件一致性检查；
- 合并版 / 分册版导出；
- Word / PDF。

### 4.3 第二阶段（后置开发，但最终作品必须完整呈现）

- 思维导图；
- PPT；
- 教材导入与内容识别；
- 课外拓展。

### 4.4 支撑能力（必须出现在演示中，但不单独做功能巡游）

- 专业数据库；
- 专业知识库 / 课程资料；
- 质量检查与依据展示；
- AI 辅助。

### 4.5 明确不做

- 独立课堂投屏模式；
- 学生端账号与学生设备适配；
- 学校管理、违章留痕、教师处罚；
- 通用聊天机器人；
- 多个功能模块的巡游展示；
- 强制导出审批；
- 用系统判断替代教师教学决定。

## 5. 核心概念与数据模型

### 5.1 备课项目 PreparationProject

一个典型工作任务对应一个备课项目。

```text
PreparationProject
├── identity: 专业/课程/任务
├── sources: 教材、课程资料、知识库引用
├── design: 教学目标、知识、技能、任务、重点、难点、过程
├── artifacts: 教学设计、教案、信息页、工作页、实训任务书、导图、PPT、拓展
├── checks: 质量记录、跨文件一致性问题
├── edits: 教师修改记录
├── exports: 导出记录
└── status: 草稿/审阅中/已导出
```

### 5.2 材料不是模块

所有材料都属于同一个 PreparationProject。不得把每类材料建立为独立项目或独立入口。

### 5.3 来源 Source

来源分三类：

1. 教师导入教材；
2. 校本 / 学校资料；
3. 通用公开资料。

每个来源必须携带：

- 来源类型；
- 标题；
- 位置（页码/章节/片段）；
- 是否校本；
- 是否需要教师核对。

### 5.4 设计确认 Design

在生成材料前，教师必须能确认：

- 教学目标；
- 知识点；
- 技能点；
- 工作任务；
- 教学重点；
- 教学难点；
- 教学过程。

### 5.5 教师修改 Edit

修改是逐段、可保存、可追溯的。教师修改一段，不自动改写其他材料。

### 5.6 一致性问题 ConsistencyFinding

描述：

- 涉及材料；
- 冲突内容；
- 严重程度；
- 定位；
- 建议；
- 教师处理状态（未处理 / 已修改 / 忽略）。

系统只提示，不自动统一。

### 5.7 导出 ExportRecord

记录：

- 合并版/分册版；
- Word/PDF；
- 时间；
- 项目版本。

导出前不设强制审批。

## 6. 端到端工作流

```text
进入授渔
→ 告诉授渔：我要准备《综合布线》的“网线制作”
→ 系统带入专业/课程/任务/资料
→ 选择教材：导入教材，或使用标明来源的通用版
→ 梳理并确认教学设计
→ 生成五类核心材料
→ 教师逐段修改
→ 跨文件一致性检查
→ 教师整体审阅
→ 合并版 / 分册版导出
→ Word / PDF
```

扩展材料在同一项目中呈现：

```text
→ 思维导图（可逐步展开）
→ PPT（可逐步展开）
→ 课外拓展（独立材料）
```

## 7. 功能需求

### F-01 课程与任务入口

**需求**

教师能表达“我要准备哪门课的哪个任务”，系统自动带入相关上下文。

**行为**

- 选择专业、课程、典型工作任务；
- 或直接输入任务名称后选择匹配结果；
- 系统展示已带入的课程、任务、知识包/资料状态；
- 不要求教师重复填写专业和课程。

**验收**

- 选择“计算机网络应用 / 综合布线 / 网线制作”后，工作空间显示正确上下文；
- 切换任务时，不残留上一任务的内容。

### F-02 教材导入与识别

**需求**

教师可以导入一本教材，系统识别其中的文字内容，作为项目依据。

**行为**

- 支持至少一种正式文档格式的实际导入；
- 展示识别出的章节/页码/文本；
- 教师可以指定本次使用的页码范围或章节；
- 明确标注“来自教师导入教材”；
- 识别失败时给出明确原因，不伪造内容。

**验收**

- 能实际导入一份教材文件；
- 能看到识别后的文本；
- 能在生成材料中引用该教材内容。

> 实现约束：扫描件识别能力需在开发前做技术验证；若无法识别，必须明确提示，不得假装成功。

### F-03 无教材时的通用版

**需求**

教师只给课题时，授渔仍可给出可用起点，但不能冒充本校教材。

**行为**

- 生成通用版内容；
- 显著标注“通用资料，不是本校教材，需要核对”；
- 每条关键内容保留来源说明；
- 教师可在后续导入教材替换依据。

**验收**

- 只输入“网线制作”也能进入流程；
- 页面明确显示通用版提示；
- 不出现“本校教材/学校标准”的错误表述。

### F-04 教学设计确认

**需求**

在生成材料前，教师确认这堂课到底教什么。

**行为**

- 展示教学目标、知识、技能、任务、重点、难点、过程；
- 教师可以直接修改；
- 教师可以确认并继续；
- 未确认时可以保存草稿。

**验收**

- 教师修改教学目标后，后续材料使用修改后的版本；
- 教师不确认时，不进入正式材料生成。

### F-05 五类材料生成

**需求**

根据确认后的教学设计，生成同一项目的五类核心材料。

**行为**

- 教学设计；
- 教案；
- 信息页；
- 工作页；
- 实训任务书；
- 每份材料结构完整、可阅读、可编辑；
- 关键内容带来源；
- 不自动导出。

**验收**

- 五类材料均存在；
- 同一任务、同一目标在各材料中不矛盾；
- 教师可以逐份打开。

### F-06 逐段编辑与确认

**需求**

教师对每段内容拥有真正的编辑权。

**行为**

- 可直接改文字；
- 可替换例子；
- 可删除内容；
- 可增加内容；
- 保存后只影响当前材料；
- 不自动改写其他材料；
- 修改后保留版本记录。

**验收**

- 修改教案中的步骤，工作页不自动改变；
- 刷新后修改仍在；
- 修改记录可查看。

### F-07 跨文件一致性检查

**需求**

检查同一项目不同材料之间是否互相矛盾。

**行为**

- 检查任务名称、步骤、学时、目标、评价等关键实体；
- 展示涉及的两份材料与具体位置；
- 给出提示，不自动修改；
- 教师可标记已处理或忽略；
- 检查结果可重新运行。

**验收**

- 教案与工作页步骤不一致时能提示；
- 点击问题能定位到对应材料；
- 教师忽略后不改变内容。

### F-08 整体审阅

**需求**

教师从头到尾检查整套材料。

**行为**

- 按材料顺序连续阅读；
- 显示材料之间的关系；
- 显示未处理的一致性问题；
- 允许返回任意材料修改；
- 不要求教师再次逐段确认。

**验收**

- 可以连续浏览五类材料；
- 未处理问题可见；
- 修改后回到审阅位置不丢失。

### F-09 导出

**需求**

教师自主决定是否导出，并拿到合并版与分册版。

**行为**

- 合并版：一个完整文件；
- 分册版：五份独立文件；
- 格式：Word 和 PDF；
- 导出前只提示，不设强制审批；
- 导出成功记录类型、时间、版本；
- 导出失败不记录成功。

**验收**

- 合并版和分册版均可下载；
- Word 和 PDF 内容一致；
- 分册版每份文件可单独打开。

### F-10 思维导图

**需求**

生成一张讲清知识关系、可逐步展开的思维导图。

**行为**

- 从教学设计生成；
- 任务大纲单独呈现；
- 整机/对象外观与要解决的问题进入导图；
- 教师可逐步展开；
- 教师可按自己的节奏控制下一步；
- 支持查看/整理/演示；
- 不做真实课堂投屏；
- 与知识图谱严格区分。

**验收**

- 导图内容与本课教学设计一致；
- 可以逐步展开，不是一次性全部显示；
- 不出现“知识图谱”混用。

### F-11 PPT

**需求**

生成与教学设计一致的 PPT，可逐步查看。

**行为**

- 由确认后的教学设计生成；
- 与教案、导图内容一致；
- 可逐页查看；
- 支持逐步展示；
- 教师可编辑或至少替换内容；
- 本次不做课堂投屏。

**验收**

- PPT 页数与教学环节对应；
- 与教案不矛盾；
- 可逐步查看。

### F-12 课外拓展

**需求**

为当前教学任务生成一份独立的学生拓展任务。

**行为**

- 与当前任务相关，但不进入核心教学流程；
- 面向学生，可独立使用；
- 教师可选择是否布置；
- 例如“不同网络环境下网线制作方案的选择”；
- 不污染核心五类材料。

**验收**

- 拓展材料独立存在；
- 与核心任务有关联；
- 教师可选择是否纳入导出。

### F-13 专业知识与质量支撑

**需求**

专业数据库、知识库、质量检查必须支撑主流程，不单独做功能展示。

**行为**

- 课程与任务来自专业体系；
- 材料引用课程知识/资料并标注来源；
- 质量检查展示规则依据与问题位置；
- 专业数据与知识库不要求教师单独巡游。

**验收**

- 演示中能看到课程身份来自专业数据；
- 能看到知识来源；
- 能看到质量依据与教师处理。

### F-14 保存与恢复

**需求**

教师离开或刷新后能继续当前项目。

**行为**

- 自动保存当前项目；
- 刷新恢复当前项目与材料；
- 显示保存状态；
- 失败时明确提示；
- 不丢失教师修改。

**验收**

- 修改后刷新仍在；
- 关闭重开可回到当前项目。

## 8. AI 需求

### 8.1 触发

- 必须由教师明确发起；
- 不自动生成、不自动推荐、不自动改写；
- 教师可以跳过 AI 建议。

### 8.2 职责

- 整理；
- 查资料；
- 分析；
- 生成初稿；
- 发现问题；
- 检查材料矛盾。

### 8.3 权限

AI 不能：

- 决定教什么；
- 决定怎么教；
- 覆盖教师修改；
- 冒充本校教材；
- 替教师决定是否导出；
- 替学校做责任判断。

### 8.4 来源

- 每条关键内容可追溯到教材/资料/知识库/通用来源；
- 通用内容必须标注；
- 校本内容与通用内容分开显示。

### 8.5 可用性

- 比赛演示不得依赖外部模型密钥才能走通核心流程；
- AI 不可用时，明确说明，不伪造生成结果；
- 质量检查的核心规则应有本地可运行版本。

> 如使用外部 AI，需在 PRD 技术评审时确认隐私、网络、密钥和失败降级策略。

---

## 9. 交互与体验要求

- 一个工作任务 = 一个工作空间；
- 不按“功能”拆页面；
- 不重复录入；
- 不在模块之间反复跳转；
- 默认路径让新教师走通；
- 熟手可以跳过和加速；
- 教师修改当前材料，其他材料不自动变；
- 跨文件冲突只提示；
- 导出前不设审批；
- 界面普通、顺手、不炫技；
- 不使用花哨动效、渐变、装饰抢注意力；
- 支持桌面浏览器独立操作；
- 重要操作有明确的保存/失败/完成反馈。

---

## 10. 非功能要求

| 类别 | 要求 |
|---|---|
| 可用性 | 评委无需作者讲解可独立完成主流程 |
| 数据 | 项目、修改、来源、导出记录可持久化 |
| 隐私 | 教材、学生信息、项目内容默认本地保存 |
| 兼容 | 主流桌面浏览器；移动端不是本期重点 |
| 性能 | 生成、保存、导出有明确状态，不出现无响应 |
| 可追溯 | 来源、修改、质检、导出版本可查 |
| 降级 | AI/识别失败时明确提示，不伪造成功 |
| 可维护 | 材料结构与来源模型可扩展其他课程 |

## 11. 验收场景

### 11.1 主验收路径

1. 评委打开网站；
2. 选择“计算机网络应用 / 综合布线 / 网线制作”；
3. 看到课程、任务、资料上下文自动带入；
4. 导入一份教材并看到识别结果；
5. 确认教学设计；
6. 生成五类核心材料；
7. 修改教案中的一段；
8. 看到工作页未被自动修改；
9. 运行跨文件检查，看到不一致提示；
10. 自行决定忽略或修改；
11. 整体审阅；
12. 导出合并版与分册版；
13. 获得 Word 和 PDF；
14. 查看思维导图与 PPT 的逐步展开；
15. 看到课外拓展作为独立材料存在。

### 11.2 评委应得出的判断

> 授渔不是套壳生成工具，而是把课程、任务、教学设计和多种教学材料组织成一套可上课成果的教师工作助手。

### 11.3 反向验收

出现以下任一情况，视为不通过：

- 需要作者解释才能看懂；
- 教师要在多个模块之间找功能；
- 同一个信息被反复填写；
- 五类材料互相对不上却不提示；
- AI 自动覆盖教师修改；
- 通用内容冒充本校教材；
- 导出依赖强制审批；
- 只展示功能巡游，没有完整成果；
- 界面花哨、干扰主任务；
- 教材导入是假入口；
- 导图/PPT 不能逐步展开。

## 12. 风险与待评审项

| 风险 | 影响 | 处理 |
|---|---|---|
| 教材扫描件无法识别 | 教材导入要求无法满足 | 开发前技术验证；明确支持格式；失败提示 |
| 外部 AI 不可用 | 演示中断 | 本地降级；明确标识 |
| 综合布线专业内容不足 | 生成内容空泛 | 建立课程/任务/来源包，教师核对 |
| 五类材料结构过重 | 教师觉得复杂 | 以任务为中心，不按模块拆分；逐段编辑 |
| 导出格式不一致 | 评审认为不专业 | Word/PDF 同源生成，导出前预览 |
| 导图/PPT 与材料脱节 | 内容矛盾 | 统一从教学设计生成；纳入一致性检查 |
| 版权/隐私 | 教材内容外泄 | 本地存储；不上传公开网络；来源标注 |
