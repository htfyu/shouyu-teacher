# 部署说明

## 1. 前端：GitHub Pages

当前固定地址：<https://htfyu.github.io/shouyu-teacher/>

旧地址 `https://htfyu.github.io/jiangbei-teacher/` 由独立的重定向仓库保留，自动跳到新地址（含 hash 路由）。

站点是纯静态 ES Module，无构建步骤：

```text
index.html
assets/
js/
.nojekyll
```

### 首次部署

1. 把上述文件推送到仓库 `main` 分支根目录；
2. GitHub → Settings → Pages：
   - Source: Deploy from a branch
   - Branch: `main`
   - Folder: `/ (root)`
3. 等待构建完成；`.nojekyll` 防止 Jekyll 忽略某些文件。

### 更新

直接替换/提交文件即可。因 `app.js` 可能被 CDN 缓存，更新后可加查询参数验证：

```text
https://<user>.github.io/shouyu-teacher/?v=2
```

### 自定义域名

在 Pages 设置中填写域名，并在仓库根目录添加 `CNAME`；同时配置 DNS。启用 HTTPS。

## 2. 静态资源与依赖

- `js/*.js`：应用模块；无打包、无 CDN 依赖（体验 AI 除外）；
- `assets/vendor/`：PDF.js、mammoth、SheetJS、JSZip，约 4MB；文件解析 / DOCX / XLSX 导出时按需加载；
- `assets/vendor/pdfjs/cmaps/`：PDF 中文 CMap；必须随站点一起部署；
- OCR：默认不加载；用户同意后从 jsDelivr 懒加载 Tesseract.js 与语言数据。如学校网络禁止外部 CDN，请把资源改为校内托管并修改 `js/files.js` 的 OCR 地址。

## 3. 安全后端（AI）

GitHub Pages 不能保存 API Key，也不能运行服务端逻辑。生产 AI 必须部署 `server/`：

- Cloudflare Worker（推荐）：见 `server/README.md`；
- Vercel Function（备选）：见 `server/vercel/README.md`。

前端设置中的代理 endpoint 必须与部署地址一致，`ALLOWED_ORIGINS` 必须包含实际前端 Origin。

**未部署安全后端时，线上只能使用本地模式或无密钥体验通道。** 本项目当前没有部署生产代理。

## 4. 安全响应头

GitHub Pages 不能自定义响应头（CSP、HSTS、X-Frame-Options 等受限）。生产建议：

- 在 Cloudflare 前面板配置安全响应头；
- 或将静态站点放在支持自定义头的静态托管上；
- 不要因为缺少 CSP 就认为前端可以接收未转义 HTML；应用内部仍执行输出转义。

## 5. 缓存策略

- HTML / JS / CSS 使用普通静态缓存；更新后需要强刷或版本参数；
- `assets/vendor/` 可长期缓存；
- IndexedDB 数据在用户浏览器，不随部署更新。

## 6. 本地开发

```bash
python -m http.server 5598 --bind 127.0.0.1
# 或 npm run serve
```

不要用 `file://` 打开；ES Module 会被浏览器阻止。
