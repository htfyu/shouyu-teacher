# 匠备 · 工学一体化教师助手 / 作品设计方案

- **作品名称：** 匠备 · 工学一体化教师助手
- **赛道：** 教师助手 AI 智能体
- **作品形态：** 可公开访问的网页端智能体（静态前端 + 本地知识库 + 多步骤教学工作流）
- **固定地址：** https://htfyu.github.io/jiangbei-teacher/
- **版本：** V1.0 · 知识库 2026.11 校本示例版

## 一、真实痛点

技工院校 / 职业院校教师做工学一体化备课时，常见四个问题：

1. **结构复杂、重复劳动多：** 教案、任务单、工作页、评价表四套材料需要相互对齐，格式与时间分配容易出错；
2. **资料分散、引用困难：** 课程标准、评价制度、实训安全规程散落在不同文件，回答容易“凭印象”；
3. **通用 AI 容易瞎编：** 给出的教案看起来完整，但设备、企业标准、安全条款无法追溯，存在教学与安全风险；
4. **需求不完整时直接生成：** 学情、课型、学时、设备台数未确认，输出只能“泛泛而谈”，老师还要重写。

因此作品不做“万能聊天助手”，而是把**一个有边界、有依据、有固定产出**的备课流程做深。

## 二、目标与边界

**目标：** 输入“专业 + 课程 + 工作任务 + 课型 / 学时 + 学情 + 设备”，输出可修改、可上课、可审核的教案 / 任务单 / 工作页 / 评价表；支持电工 / PLC 实训安全查询；把脱敏听课记录整理为证据型评课意见。

**明确不做：**

- 学生心理诊断、家庭情况处理；
- 成绩预测、学生排名、标签化评价；
- 人事、财务、法律、采购判断；
- 医疗与现场急救决策；
- 涉密、敏感、未脱敏校内数据的处理；
- 替代教师做最终教学决定或替代现场安全交底。

超范围时统一说明“不在我的知识范围内”，并给出咨询方向。

## 三、系统与工作流

```text
教师任务
  ↓
参数澄清（表单必填 + 对话追问 + 条件记忆）
  ↓
知识检索（9 份材料 / 51 个章节级片段）
  ↓
结构化生成（教案 / 任务单 / 工作页 / 评价表 / 安全清单 / 评课意见）
  ↓
引用绑定（每个模块附依据，点击可回溯原文）
  ↓
合规自检（个人信息、审核提示、安全边界）
  ↓
教师人工审核 → 复制 / Word / PDF → 使用
```

多步骤工作流（界面可见）：读取条件 → 检索依据 → 对齐目标与评价 → 生成结构 → 合规自检。

## 四、知识库设计

当前为**可替换的校本示例库**，明确不对应任何正式文件：

| 编号 | 材料 | 作用 |
|---|---|---|
| KB-01 | 工学一体化课程设计指引 | 目标写法、学情、目标—活动—评价一致性 |
| KB-02 | 工学一体化教案模板 | 教案结构与流程表字段 |
| KB-03 | 学习任务单模板 | 学生版目标、交付物、记录栏 |
| KB-04 | 工作页编写规范 | 六步结构、问题链、安全与评价嵌入 |
| KB-05 | 电工与 PLC 实训室安全规程 | 准入、用电、调试、异常处置、收尾（仅限此两类场所） |
| KB-06 | 课堂质量评价表 | 五维评分与评语写法 |
| KB-07 | 听课评课框架 | 证据提取、五段式评课、建议写法 |
| KB-08 | 学业评价与成绩评定 | 过程 60% + 终结 40%、主体权重、补做 |
| KB-09 | 数据安全与 AI 边界 | 不上传清单、最小化、人工审核、事件处置 |

检索做法：中文二元 / 三元词项、标签与标题加权、场景权重；结果细到章节，页面显示引用编号（如 `KB-05 §04`），可展开原文。

**可扩展：** 保持 `KB_DOCS` 结构，替换 / 新增材料即可；检索、统计、引用面板自动更新。模板库同理。

## 五、功能清单（对应比赛合格线）

1. **边界与角色：** 首页能力边界说明；超范围识别规则；明确咨询方向；
2. **知识库与依据：** 真实可检索的结构化材料；回答附章节引用；无依据时承认不知道；
3. **任务闭环：** 教案 / 任务单 / 工作页 / 评价表 / 安全清单；固定结构、分块复制、Word / PDF / Markdown 导出；
4. **追问与澄清：** 参数表单必填校验；对话缺参时追问；多轮条件记忆；支持“把学时改成 6”等中途修改；
5. **安全合规：** 本地处理、不上传；敏感格式检测；人工审核提示；安全条款以现场规程为准。

## 六、界面设计

- 视觉转译自手绘线稿：**纯白背景、黑色 1px 线条、硬阴影、直角边框、宋体大标题 + 等宽字标签**；
- 保留手绘稿的左栏（新对话 / 历史对话）、主区问候、输入框与文件入口；
- 增加真实可用功能：5 个场景入口、参数表单、结果卡片、引用面板、合规自检、历史记录、反馈；
- 响应式：桌面为“对话 + 依据”双栏，移动端依据面板变为抽屉；
- 无外部字体 / 图片 / UI 框架依赖，离线可打开（需静态服务器）。

## 七、数据安全与合规

- **架构层面：** 纯静态前端，无后端、无第三方请求、无外部大模型；输入不上传；
- **最小化：** 只收集任务必需信息；学情使用班级级描述；
- **检测：** 手机号、身份证号、邮箱、学号、姓名前缀等格式检测，命中后阻止处理；
- **存储：** 历史与反馈只存在当前浏览器；换设备不同步；可逐条删除；清缓存即清除；
- **输出定位：** 全部标注“AI 辅助草稿 / 待人工审核”，每份附合规自检；
- **安全：** 安全知识库仅覆盖电工 / PLC；其他场所明确说未收录，不套用、不编造。

## 八、创新点 / 差异化

1. **“会拒绝”优先于“会闲聊”：** 超范围与学生标签请求有硬规则，不是靠概率；
2. **知识库没有就承认：** 安全查询和评课评分都设置“无依据不输出”的门槛；
3. **任务闭环而非单点生成：** 教案 → 任务单 / 工作页 → 评价表，条件在多轮中延续；
4. **引用绑定到章节：** 每个模块可单独回溯依据，方便教研与审核；
5. **可替换、可扩展：** 知识库、模板均为配置文件，换学校 / 换专业不需要改页面；
6. **本地优先：** 打开即用、无需 API Key，避免学校数据出浏览器，适合低配置机房与公开演示。

## 九、可运行与可推广

- 公网固定地址访问，无安装；
- 演示只需浏览器，3 分钟可跑通主闭环；
- 知识库与模板可复制到其他专业 / 院校；
- 若需接入学院系统或大模型，可增加后端代理、权限控制与脱敏层，保留现有引用、模板与合规约束。

## 十、已知限制与后续计划

- 演示知识库为示例，需学校替换、审核；
- 本地工作流的开放问答和长文润色能力有限；
- 内置任务画像覆盖部分工科专业，其他专业使用通用结构；
- PDF 依赖浏览器打印，分页需人工检查；
- 个人信息检测不能覆盖所有格式，必须保留人工检查；
- 后续计划：补充更多专业任务画像、引入后端安全接入大模型、增加真实试用反馈与学情聚合看板（只使用脱敏数据）。

## 十一、真实性声明

本作品不虚构用户数量、提效比例或试用单位。当前可验证的是：网站可运行、知识库可检索、引用可回溯、结果可导出、边界可触发。建议在正式提交前邀请 1—2 位同事按《演示脚本》真实使用，并用站内反馈模板记录可核验的试用证据。
