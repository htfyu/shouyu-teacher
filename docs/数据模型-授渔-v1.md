# 授渔数据模型 v1

> 状态：待审阅  
> 日期：2026-11-18  
> 依据：PRD-授渔-v1、页面与交互-授渔-v1  
> 本文定义产品级数据关系，不规定具体数据库实现。

---

## 1. 原则

1. 一个典型教学任务 = 一个 PreparationProject；
2. 五类核心材料与扩展材料都属于同一个项目；
3. 来源、设计、材料、检查、修改、导出互相引用，不各自复制；
4. 教师修改只影响当前材料；
5. 系统只提示冲突，不自动同步；
6. 所有内容都可追溯到来源；
7. 旧项目数据采用加法迁移，不删除、不重建；
8. 通用资料与校本资料必须区分；
9. AI 生成的内容与教师修改的内容分别记录；
10. 导出文件来自项目当前状态，不另生成一套内容。

## 3. PreparationProject

```json
{
  "id": "prep_xxx",
  "schema": "shouyu.prep.v1",
  "status": "draft",
  "identity": {
    "majorId": "major-network",
    "majorName": "计算机网络应用",
    "courseId": "course-cabling",
    "courseName": "综合布线",
    "taskId": "task-cable-making",
    "taskName": "网线制作"
  },
  "sourceMode": "textbook",
  "createdAt": "ISO",
  "updatedAt": "ISO",
  "lastSavedAt": "ISO"
}
```

### status

- `draft`：草稿；
- `design_confirmed`：教学设计已确认；
- `materials_ready`：材料已生成；
- `reviewing`：审阅中；
- `exported`：已导出；
- `archived`：归档。

状态只用于表示进度，不强制阻断。

## 4. SourceRef

```json
{
  "id": "src_xxx",
  "type": "textbook",
  "title": "综合布线教材（教师导入）",
  "origin": "teacher_import",
  "isSchoolBased": true,
  "needsReview": false,
  "location": {
    "page": 42,
    "chapter": "项目三",
    "fragment": "网线制作步骤"
  },
  "text": "识别后的文本",
  "createdAt": "ISO"
}
```

### type

- `textbook`：教师导入教材；
- `school`：学校/校本资料；
- `knowledge`：专业知识库；
- `course`：课程资料；
- `generic`：通用公开资料；
- `teacher`：教师自己的说明/经验。

### 必填规则

- 标题；
- 来源类型；
- 是否校本；
- 是否需要核对；
- 位置或片段；
- 原始文本/引用。

### 显示规则

- `generic` 必须显示“通用资料，不是本校教材”；
- `needsReview=true` 必须显示核对提示；
- 不允许把 `generic` 显示为 `school`。

## 5. TeachingDesign

```json
{
  "objectives": [
    { "text": "能按标准完成网线制作", "sourceIds": ["src_1"] }
  ],
  "knowledge": [],
  "skills": [],
  "task": {
    "name": "网线制作",
    "description": ""
  },
  "keyPoints": [],
  "difficulties": [],
  "process": [
    { "stage": "导入", "minutes": 5, "content": "" }
  ],
  "confirmed": false,
  "confirmedAt": null
}
```

### 规则

- 未确认时不能正式生成材料；
- 每项可引用来源；
- 教师可增删改；
- 过程安排必须与材料中的步骤一致；
- 确认后修改，需要让相关材料标记“设计已变更”。

---

## 6. Artifact

```json
{
  "id": "doc_lesson_plan",
  "type": "lesson_plan",
  "title": "网线制作 · 教案",
  "status": "edited",
  "version": 2,
  "sections": [
    {
      "id": "sec_1",
      "heading": "一、教学基本信息",
      "blocks": []
    }
  ],
  "sourceIds": ["src_1"],
  "updatedAt": "ISO"
}
```

### type

- `teaching_design`；
- `lesson_plan`；
- `information_page`；
- `worksheet`；
- `practical_task_sheet`；
- `mind_map`；
- `slide_deck`；
- `extension_task`。

### 材料状态

- `empty`；
- `generated`；
- `edited`；
- `checked`；
- `has_issue`；
- `confirmed`。

### 规则

- 一份材料属于一个项目；
- 材料之间不共享可变正文对象；
- 引用来源只存 ID；
- 修改一份材料不写其他材料；
- 生成过程可重建，但教师修改必须保留。

---

## 7. Block

材料内容是结构化块，不存成一整段不可编辑文本。

```json
{
  "id": "blk_1",
  "type": "paragraph",
  "text": "本课以网线制作任务为载体……",
  "sourceIds": ["src_1"],
  "origin": "ai",
  "editedByTeacher": false
}
```

### type

- `paragraph`；
- `list`；
- `table`；
- `steps`；
- `image`；
- `callout`；
- `question`；
- `assessment`；
- `slide`；
- `mind_node`。

### origin

- `ai`：AI 生成；
- `teacher`：教师新增/修改；
- `source`：教材/资料直接引用。

### 规则

- 教师修改后 `editedByTeacher=true`；
- AI 不覆盖 `editedByTeacher=true` 的块；
- 删除的块保留历史版本，不物理丢失。

## 8. ConsistencyFinding

```json
{
  "id": "find_xxx",
  "kind": "cross_document",
  "severity": "warning",
  "message": "教案与工作页的任务步骤不一致",
  "materials": ["doc_lesson_plan", "doc_worksheet"],
  "locations": [
    { "artifactId": "doc_lesson_plan", "sectionId": "sec_3", "blockId": "blk_8" },
    { "artifactId": "doc_worksheet", "sectionId": "sec_2", "blockId": "blk_4" }
  ],
  "basis": "同一教学任务",
  "suggestion": "在工作页补充任务，或修改教案",
  "teacherAction": "unresolved",
  "createdAt": "ISO"
}
```

### teacherAction

- `unresolved`；
- `ignored`；
- `fixed`；
- `deferred`。

### 规则

- 不自动修改材料；
- 教师操作后保留记录；
- 重新检查可以生成新结果；
- 导出前不阻断；
- 问题应能定位到具体块。

---

## 9. QualityRecord

```json
{
  "id": "quality_xxx",
  "at": "ISO",
  "overall": 84,
  "status": "needs_review",
  "layers": {},
  "dimensions": [],
  "findings": []
}
```

### 规则

- 质量分数不是学校审核结论；
- 必须显示依据和限制；
- 不能伪造满分；
- 没有检查时不能显示假分数；
- 记录可追溯。

---

## 10. Version

```json
{
  "id": "ver_2",
  "version": 2,
  "at": "ISO",
  "reason": "teacher_edit",
  "snapshot": {
    "design": {},
    "artifacts": []
  }
}
```

### 规则

- 重要修改形成版本；
- 保留最近若干版本；
- 恢复版本前让教师确认；
- 恢复不删除当前版本；
- 不因版本记录改变导出结果。

---

## 11. ExportRecord

```json
{
  "id": "exp_xxx",
  "at": "ISO",
  "format": "pdf",
  "scope": "combined",
  "version": 3,
  "status": "success"
}
```

### scope

- `combined`；
- `split`；
- `split_part`。

### format

- `docx`；
- `pdf`。

### 规则

- 成功才写入；
- 失败保留错误原因；
- 合并版/分册版内容同源；
- 导出记录属于项目。

---

## 12. AI Action

```json
{
  "id": "ai_xxx",
  "action": "generate_materials",
  "requestedBy": "teacher",
  "at": "ISO",
  "sourceIds": [],
  "affectedArtifacts": [],
  "result": "success",
  "model": "local-or-configured"
}
```

### 规则

- 只有教师发起才记录；
- 生成结果不直接覆盖教师内容；
- 失败可重试；
- 记录来源和影响范围；
- 具体模型/密钥不写入作品内容。

---

## 13. 数据完整性规则

1. 一个项目只能对应一个教学任务；
2. 五类核心材料必须存在（即使为空，也要有状态）；
3. 所有材料必须属于当前项目；
4. 来源引用不得指向不存在的来源；
5. 教师修改不得被 AI 静默覆盖；
6. 通用来源不得标记为校本；
7. 质检/一致性问题必须能定位材料；
8. 导出记录必须对应项目版本；
9. 删除项目前必须确认；
10. 旧项目迁移不得丢失原始材料。

## 14. 迁移与兼容

### 14.1 旧数据

现有成果包如果对应“课程 + 章节 + 任务 + 材料”，迁移为 PreparationProject：

- 保留原 ID；
- 补齐 `sourceMode`、`identity`、`artifacts`；
- 旧质量记录迁入 `QualityRecord`；
- 旧版本迁入 `Version`；
- 旧导出记录迁入 `ExportRecord`；
- 不删除旧字段；
- 不更改原项目标题。

### 14.2 迁移原则

- 加法迁移；
- 可回滚；
- 不重建数据库；
- 不丢失教师修改；
- 迁移失败时保留原记录并提示；
- 不把旧数据伪装成新生成内容。

### 14.3 路由兼容

具体路由在实现阶段确定；原则：

- 旧项目仍可打开；
- 旧导出仍可查看；
- 旧链接不能直接 404；
- 新流程不要求教师重新建项目。

## 16. 数据模型结论

授渔的产品数据结构不是“多个功能模块的数据表”，而是一个教学工作项目的完整记录：

```text
项目
├── 身份
├── 来源
├── 教学设计
├── 多种材料
├── 检查
├── 修改/版本
└── 导出
```

所有专业数据、知识资料、AI、质量和导出记录都围绕这个项目存在。
