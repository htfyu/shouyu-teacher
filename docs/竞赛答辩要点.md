# 竞赛答辩要点：9 个问题

## 1. 这个项目到底解决什么痛点？

职业院校教师做一门工学一体化课程，通常要在招生简章、专业介绍、课程表、旧教案、工作页、评价表、设备说明书之间反复搬运：

- 专业课程信息散落在 Excel、网页、个人电脑；
- 教案、工作页、任务书、评价表各自编写，任务名称、学时、目标经常对不上；
- 生成式 AI 能写长文，但无法保证来源、设备参数和学校标准；
- 学校要审核时，看不到“这句话依据在哪里、问题在哪里、谁改过”。

授渔把这条链变成一条可追溯工作流：**专业数据库 → 课程知识包 → 10 类资源共享任务上下文 → 规则质检 → 教师审核 → 标准文档**。

## 2. 和普通 AI 教案生成器有什么差异？

| 普通工具 | 授渔 |
|---|---|
| 用户输入一段提示词 | 从专业库选系/组/专业/课程/章节/任务 |
| 生成一篇教案 | 一次生成 10 类互相匹配的资源 |
| 来源不可见 | 每个知识点/任务有 `PK`/`S` 引用 |
| 无法质检 | 10 维规则、证据、位置、建议、人工复核 |
| 没有版本/审核 | 成果库、版本、审核状态、完整备份 |
| 现场依赖网络/模型 | 固定案例可离线运行 |

核心差异不是“模型更强”，而是**把专业知识和质量证据结构化**。

## 3. 创新点是什么？

1. **专业知识装配**：课程知识包不是一段提示词，而是章节、知识点、任务、设备、安全、评价、来源的结构化对象。
2. **10 类资源共享上下文**：不是复制同一段文字，而是同一任务在 10 种文档结构中的一致展开。
3. **可解释质检**：分数来自规则和证据，能定位到文档/章节，能自动修复的结构问题才自动修。
4. **来源分级与审核封顶**：待审核知识包最高 84 分，行业参考最高 72 分，防止“模板分冒充质量”。
5. **知识图谱只画有数据的边**：没有知识包的课程不伪造关系。
6. **教师审核闭环**：成果可审核、可版本化、可导出，不把 AI 内容直接冒充官方文件。

## 4. 专业内容准确性如何保证？

分四层：

- **课程身份**：4 门标杆课程分别使用来源表比对后的 S2/S3、S6/S7/S8、S20/S21/S22、S44/S45 官方专业来源；原表错配编号保留并警示。
- **知识点/任务**：来自 `PK-PLC-01/02`、`PK-ROBOT-01/02`、`PK-CAR-01/02` 校本示例，每个知识点/任务有 `§` 引用，页面和导出都能追溯。
- **质量规则**：A 结构、B 专业知识、C 教师专家三层；B 层检查知识点覆盖、来源、设备、参数和步骤，不能自动判断的内容列入教师审核。
- **人工审核**：知识包状态是“待教研组审核”，设备参数、I/O 地址、安全条款必须人工核对；系统不声称已通过学校审核。

我们主动暴露了原表 S20/S27 来源编号错配，而不是掩盖它。这是准确性的一部分。

## 5. 如何体现工学一体化？

不是加一个“工学一体化”标签，而是按真实工作过程组织：

- 典型工作任务（物料分拣站 I/O 分配与接线检查）；
- 工作情境、交付物、实施步骤、设备、安全；
- 资讯 → 计划/决策 → 实施 → 检查 → 评价；
- 学生工作页、任务书、实训指导书、评价量规、反思表；
- 教师活动/学生活动/证据三者对应；
- 教学目标可评价，评价权重合计 100%。

质量检测会检查任务真实性、活动合理性、实训完整性、安全、评价匹配和跨文档一致性；教案阶段分钟合计会与“学时 × 45 分钟”核对，工作页/任务书步骤、课件知识点覆盖、工作页安全提示也会检查。

## 6. 质量检测是不是“自己给自己打分”？

不是。规则是公开的、可在代码中检查的：

- 10 个维度、固定权重、可配置；
- 每个问题有等级、位置、建议、依据；
- 分数可复现，单元测试覆盖；
- 不能自动判断的内容标“需人工审核”；
- 未审核知识包封顶 84，行业参考封顶 72；
- 分数不是学校官方认定。

它更像“教学资源静态检查器 + 教研提示”，不是模型裁判。

## 7. 到底节省了什么？

节省的是**重复搬运和一致性返工**，不是省掉教师判断：

- 原来分别写教案、工作页、任务书、评价表，现在共享课程/任务/学时/目标；
- 原来手工核对任务名称、评价权重，现在规则检查；
- 原来导出后还要补封面、目录、签字区，现在标准模板；
- 原来改一版就找不到旧版，现在成果库保留最近 4 个内容版本；
- 原来 AI 生成后无法解释来源，现在每节有引用。

不承诺“一键替代教师”，也不编造节省的具体小时数；新增「教学应用成效」模块，只有真实录入时才显示传统/智能备课对比，没有数据就显示“尚未采集”。

## 8. 如何证明系统真实可用，而不是 PPT？

- 公开地址可直接操作：<https://htfyu.github.io/shouyu-teacher/>；
- `#/demo` 固定案例可重复运行；
- 10 类资源真实生成，不是占位图；
- 质量报告三层/10 维真实计算；
- DOCX 可下载，含封面、目录、10 份文档、来源、签字区；
- 94 项单元测试 + 73 项 E2E，覆盖工作台、我的课程、课程工作空间、六步备课、项目工作区、专业库、4 门知识包、三层质检、图谱、演示、应用成效、备份恢复、移动端；
- 代码、数据、测试、审计报告全部在仓库；
- 明确列出未实现项（官方审核、云同步、生产 AI 代理、逐段 diff 等）。

## 9. 如何推广到更多专业和学校？

按“一个专业包 → 多个专业包 → 学校知识库”的路径：

1. **模板化知识包**：每门课按同一 JSON 结构建设 4 章/15 知识点/5 任务，逐条来源。
2. **教研组共建**：课程负责人审核知识点、设备、安全、评价；审核状态进入系统。
3. **先用 1—2 门课试点**：测量备课时间、返工次数、审核问题数，不先做大而全。
4. **学校级部署**：静态站点可直接放学校内网/对象存储；需要账号/云端时再接后端，不在 GitHub Pages 上做假云。
5. **质量规则本地化**：学校可调整 10 维权重、增加校本安全条款。
6. **与现有平台共存**：导出 DOCX/XLSX 进入学校归档；不强迫替换现有教务系统。

推广的边界：没有学校正式审核文件，就不把知识包标成“已审核”；没有真实试点数据，就不宣称“提升 X%”。
