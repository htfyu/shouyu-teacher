## 一、实际导入了什么

脚本直接读取工作簿的 6 个工作表，没有把 Excel 当成一张展示表，也没有只导入专业名称。

| 工作表 | 原始记录 | 导入结果 |
|---|---:|---|
| 学院专业架构 | 75 行 | 75 条招生计划，保留专业代码、培养层次、学制、招生对象、校区、状态、数据年份、专业组归属核验、备注 |
| 专业课程总表 | 567 行 | 567 条课程记录，保留原表行号、专业系、专业组、专业、课程类别、阶段/版本、课程名、简介、年份、来源编号 |
| 专业详细介绍 | 56 行 | 56 个专业条目，保留培养目标、核心能力、就业方向、招生对象、学制、主要课程摘要、状态、来源编号 |
| 专业系汇总 | 6 个教学单位 + 合计 | 6 个教学单位简介；合计口径另存于 `meta.workbookSummary` |
| 信息来源与核验 | 134 行 | 134 条来源，保留名称、原始网址、发布时间、核验状态、对应专业与信息内容 |
| 数据说明与统计 | 22 条说明 | 22 条说明原文保留在 `notes` |

### 数据层级

```text
专业系（6）
└─ 专业组 / 学科组（13）
   └─ 专业条目（56）
      ├─ 招生计划（75，同一专业可有多个层次）
      └─ 课程记录（567）
         └─ 来源记录（134，按 S1…S134 关联）
```

- 13 个组包含 10 个专业群、2 个人文素养学院学科组、1 个“未纳入现行专业群”记录；均原样保留。
- 56 个专业条目包含 2 个“公共基础课程（思政与文史 / 数英与体美）”记录；没有把它们伪装成普通专业。
- 567 条课程中，12 条课程名为空，15 条课程类别为“暂无公开资料”；均保留为“未命名 / 占位课程”并标注，不删除、不猜测名称。
- 原表 484 个去重课程名称，不等于 567 条记录；同名课程在不同专业/版本下分别保留，不做静默合并。
- 原表汇总页写“54 个专业 / 480 门去重课程”，按明细实际为 56 个专业条目 / 567 条记录。页面同时显示两个口径，并解释差异来源，不擅自修改原表数字。

## 二、数据结构

生成后的 `PROGRAM_DATA` 包含：

```js
{
  meta: { college, title, version, sourceFile, counts, workbookSummary, ... },
  departments: [{ id, name, kind, summary, groupIds, majorIds, sourceIds }],
  groups: [{ id, deptId, name, kind, majorIds }],
  majors: [{
    id, seq, deptId, groupId, name, isPublicFoundation,
    trainingGoal, coreAbilities, employment, enrollment, duration,
    mainCoursesSummary, dataYear, status, sourceRaw, sourceIds,
    planIds, courseIds
  }],
  plans: [{
    id, seq, majorId, deptId, groupId, college, code, level, duration,
    target, campus, status, dataYear, groupVerification, note, isActive2026
  }],
  courses: [{
    id, seq, deptId, groupId, majorId, name, displayName,
    category, phase, intro, hasOfficialIntro, dataYear,
    sourceRaw, sourceIds, recordType, needsWork
  }],
  sources: [{ id, seq, dept, major, info, title, url, published, status }],
  notes: [{ title, text }]
}
```

ID 规则：

- `dept-01…06`
- `group-01…13`
- `major-001…056`
- `plan-001…075`
- `course-0001…0567`
- 来源 ID 使用原表 `S1…S134`

所有父级 ID 在生成阶段校验；单元测试再次检查 567 条课程、75 条计划都能关联到专业、专业组和专业系。

## 四、课程资源内容政策

每门可识别的课程显示 10 个模块：

1. 课程简介
2. 教学目标（知识 / 技能 / 职业素养）
3. 教学内容与知识体系
4. 重点与难点
5. 教学计划
6. 教学方法
7. 实训项目
8. 考核评价
9. 教学资源
10. 来源与校核说明

### 三类内容必须区分

- **原表官方**：仅课程简介在原表明确写出时显示，并标注“原表官方”；例如服务机器人相关课程、智能产品安装与调试等，共 13 条。
- **行业通用参考**：由 `js/programs-content.js` 按课程名、专业、专业组和学习领域生成；包含教学目标、模块、重难点、教学组织、实训任务、评价维度与资源建议。页面每个模块都标注“行业通用参考”，并提示“不是学院官方课程文件”。
- **待完善**：原表课程简介为空、课程名为空、课程类别为“暂无公开资料”，或该行是“课程体系说明”时，不生成具体课程知识，只保留原始记录并提示向课程负责人/教务处索取资料。

### 生成模板覆盖的学习领域

电气/电工、机械/制造、自动化/机器人/控制、汽车/交通装备、航空/低空装备、人工智能/数据、计算机/网络/信息安全、健康/照护、商贸/数字服务、农业/园林/食品、公共基础/通识。

模板会优先识别课程名（例如“电工技术”不会被专业培养目标中的“汽车行业”误判为汽车类），再使用专业群上下文兜底。生成内容只作为备课脚手架，不替代学院课程标准。

### 教师校订

- 课程详情 → “编辑课程资料”；
- 可填写 10 个模块和校核状态；
- 留空的字段继续显示系统参考；填写后显示“教师校订”；
- 保存到本机 IndexedDB，不修改原始数据表；
- 可“恢复系统参考”，也可在课程记录中修改课程名称、类别、阶段、简介；
- 课程详情支持复制全文、下载 Markdown、带入教案生成流程。

## 五、本机数据库与 CRUD

### 运行时存储

静态站点没有服务器数据库，采用两层结构：

1. **只读种子库**：`js/programs-data.js`（由 Excel 生成，随站点版本发布）。
2. **本机修订库**：独立 IndexedDB 数据库 `shouyu_programs_v1`，保存：
   - `overrides`：对原始专业/组/课程元数据的修改；
   - `custom`：教师新增的专业系 / 组 / 专业 / 课程；
   - `hidden`：从本机视图隐藏的原始记录；
   - `resources`：课程 10 个模块的校订内容。

IndexedDB 不可用时回退到 `localStorage`（`shouyu.programs.v1`），并在页面提示。原始数据不会被回写。

### 已实现的管理操作

- 新增专业系（管理数据 → 新增专业系）；
- 在专业系下新增专业组；
- 在专业组下新增专业；
- 在专业下新增课程；
- 编辑专业系 / 组 / 专业 / 课程元数据；
- 隐藏原始记录（不删除源表）并恢复；
- 删除教师自建记录；
- 有子记录时阻止删除，避免破坏层级；
- 导出 / 导入本机修订 JSON；
- 完整备份中携带专业数据库修订，恢复时一起恢复；
- “删除本机全部数据”会同时清空专业数据库修订库。

### 为什么不是服务器数据库

现有站点是 GitHub Pages 纯静态应用，原有对话、知识库、资料也采用 IndexedDB。为不破坏现有部署方式，专业库复用同一模式：版本化种子数据 + 本机修订。它支持长期保存和正常调用，但**不是跨设备同步，也不是多人共享数据库**。跨设备需要账号、后端与权限系统，未在本次范围内伪造。

## 六、页面使用

- 左侧“专业数据库”进入；
- 桌面端使用左侧树：专业系 → 专业组 → 专业；
- 窄屏使用三个级联选择框；
- 顶部搜索覆盖专业名称、培养目标、核心能力、就业方向、课程名称、课程类别、课程简介；
- 专业页可按课程类别筛选；
- 课程详情页显示记录信息、10 个资源模块、来源链接和边界说明；
- “用于备课”将专业、课程预填到既有教案生成流程。

## 七、更新数据的方法

```bash
# 1. 替换原始表
copy 广州市技师学院专业体系数据库.xlsx data\gzgj-professional-system.xlsx

# 2. 重新生成基础目录
python tools/generate_programs_data.py

# 3. 跑数据与页面测试
npm run test:unit
node tests/e2e.smoke.mjs
```

生成脚本会输出实际计数与文件大小。不要手工编辑 `js/programs-data.js`；教师修订写入 IndexedDB，不进入种子文件。

## 八、已知限制

1. 学院未公开完整的《专业人才培养方案》《课程标准》《教学计划表》全文；因此没有学时学分、官方章节、官方教材版本等字段。页面不会编造这些数据。
2. 13 条课程简介有官方原文；其余 554 条为“待完善 + 行业通用参考”。参考模板不能替代课程负责人审核。
3. 134 条来源按原表标注为“已核验（官方原文）”；本次导入没有逐条重新访问外网复核，链接可用性需教师打开原网址确认。
4. 专业组简介和系部“教学领域/就业方向”汇总由成员专业公开信息整理，页面已标注，不是学院单独发布的文件。
5. 课程资源、自建记录只保存在当前浏览器；跨设备需使用“管理数据 → 导出修订”或完整备份手动迁移。
6. 删除原始记录采用“本机隐藏”而非改写源表；这保证原始数据可追溯，但不等于学校层面的正式撤稿。
